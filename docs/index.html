lamaku-mcp

An MCP server for Lamakū, the University of Hawaiʻi's D2L Brightspace instance.

You describe a module to your AI assistant. It builds the module in your course: the pages, the uploaded video, the discussion, the assignment, the grade item. You approve each write before it happens, and everything is created hidden until you say otherwise.

MCP is the Model Context Protocol, a way for an assistant such as Claude to use tools outside its own chat window. Installing this server hands your assistant 54 tools for Brightspace. It runs on your own machine, signed in as you, with your permissions and no others.

Every other Brightspace MCP server is read-only. They check grades and due dates, which is useful and much simpler. This one writes, and most of its design is about not damaging a live course.

What it does, and what it does not

Both columns are the same answer. The right one is not a footnote, and each entry there says what to do instead.

It does

Every write route below was verified by creating a real object in a sandbox course and deleting it again.

Reads the whole course
Modules, topics, files, assignments, submissions, grades, announcements, discussions, quizzes, checklists, deadlines.
Writes content modules and pages
Authored HTML, styled from a template, placed in the module order you ask for.
Uploads media into the course
Images, video, audio, PDFs. Verified to 36 MB; the largest upload took 24 seconds.
Creates course objects
Links, announcements, assignments and their categories, grade items, discussion forums and topics, checklists.
Imports a whole course package
Common Cartridge or a Brightspace .zip. This is how quizzes and rubrics get in.
Previews every write before it lands
The first call returns what it would do and a single-use token. Nothing is written until you spend it, and it expires in five minutes.
Withholds student identities by default
Names, usernames, emails and ids are replaced with stable pseudonyms before anything reaches the model.
Creates everything hidden
Releasing content to students is a separate, deliberate step.

It does not

Verified against Lamakū at Learning Environment API version 1.96. These are the real edges, not a roadmap.

Write quiz questions directly
Brightspace exposes no route for it. Import a cartridge instead, which is verified: 4 quizzes, 17 questions, every answer key and feedback string intact.
Author rubrics
Needs API version 1.97. Lamakū serves 1.96. A Brightspace .zip import carries rubrics today.
Write grade values
Untested. The sandbox has no student enrolments, and trying it in a live section would alter a real record.
List grade items
get_grades returns the calling user's own grades. Items can be created and deleted by id, but not enumerated.
Create a course
Organisation-level administrative permission, which an instructor account does not have. Request a sandbox from UH ITS.
Touch groups, sections, attendance or awards
Not implemented, and not expressible in either import format either.
Run without a browser
Sign-in captures a session through a real window, so this does not suit CI or a headless server.
Work outside UH, provenly
OAuth is implemented against auth.brightspace.com but has never been exercised on a non-UH instance.

Before you point it at a real course

The thing worth understanding before installing is what happens when the assistant decides to write something. It cannot simply write it.

A write call returns a preview: the object it would create, the course it would land in, and a single-use token scoped to exactly that action. The write happens only when the token is spent, and the token expires after five minutes. A delete previews the object's name and, for a forum, its post count, so you see what you are about to lose.

Note

Build in a sandbox course first. Sandboxes are per-instructor and requested from UH ITS. Nothing here can undo a delete.

Student privacy works the same way, on by default rather than available on request. Names, usernames, email addresses and institutional ids are replaced with stable pseudonyms before any course data reaches the model, so Student 4b21 stays the same person across a whole session without ever being named.

What it costs to try

Node.js 20 or later
Node 22 is also tested. Earlier versions will not run it.
A Lamakū account
Any UH account with course access. Sign-in goes through UH SSO and Duo.
A sandbox course
Requested from UH ITS. Strongly recommended before you go near a live section.
An MCP client
Claude Code, Claude Desktop, or anything else that speaks MCP.
About ten minutes
Install and first sign-in. Sessions last around a day of idleness, then you sign in again.

Install it

Four steps. Each block has a copy button.

  1. Clone and build 
    git clone https://github.com/JesseTho/lamaku-mcp
cd lamaku-mcp
pnpm install
pnpm build
  2. Sign in

    A browser window opens. Complete the UH sign-in and approve the Duo prompt yourself. The session is stored on your own machine.

    node dist/cli.js login
  3. Register it with your assistant

    For Claude Code, run this from anywhere:

    claude mcp add lamaku -- node /absolute/path/to/lamaku-mcp/dist/index.js

    For another client, add the same command to its MCP configuration. The manual has the JSON.

  4. Check it worked

    Then ask your assistant to list your courses. If the session has expired, sign in again with the command from step two.

    node dist/cli.js status

Then read the manual

The manual is the reference: how a write preview actually reads, the order of operations for building a course from nothing, the page templates, what each import format carries, all 54 tools by name, and what to do when a call comes back 403.
